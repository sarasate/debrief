# Debrief — Spec

## 1. Problem

After a Claude Code session the working tree is dirty: 5–40 files, some written by Claude and some regenerated by tooling (lockfiles, `routeTree.gen.ts`, OpenAPI dumps), sometimes mixed with my own edits. `git diff` and a normal git client show all of it as one flat list. What I need is:

- the **relevant** changes first and the noise masked,
- the changes grouped by **what Claude was trying to do**, not by folder,
- a quick way to move through them (`j/k`, `space` = cleared, next),
- a per-hunk verdict (keep / revert),
- a way to send review notes **back to the Claude session** as one batch.

## 3. Data sources

### 3.1 Git (git2)
- `status`: working tree plus index against HEAD, untracked files included, ignored files excluded. Renames detected (`find_similar`).
- `diff_file(path)`: working tree vs HEAD (staged and unstaged combined; this is a review of "what changed since the last commit"). Three lines of context. Binary files → "binary file — no preview".
- A hunk id is `sha1(path + old_start + old_lines + new_start + new_lines + hunk body)`, truncated to 12 characters. It must stay stable across refreshes as long as the hunk hasn't changed.

### 3.2 Claude Code transcripts
Claude Code stores sessions as JSONL at `~/.claude/projects/<project-dir-slug>/<session-id>.jsonl`, where the slug is the absolute cwd with `/` replaced by `-`.

> **Milestone 2 starts by checking this against a real transcript on this machine.** Adapt the parser to what's actually there and write a fixture from a real (redacted) file. Don't trust this section blindly.

Expected per line: `type` (`user` | `assistant` | `summary` …), `sessionId`, `cwd`, `timestamp`, and `message.content[]` blocks. Tool calls are `{"type":"tool_use","name":"Edit"|"MultiEdit"|"Write"|"NotebookEdit","input":{"file_path":…}}`. `Bash` calls may also write files (`mv`, `sed -i`, codegen); record those commands but don't guess their paths.

Build a **ledger** for the chosen session:

```ts
interface LedgerEntry {
  path: string;          // repo-relative
  tool: "Edit" | "MultiEdit" | "Write" | "NotebookEdit";
  timestamp: string;
  turn: number;          // index of the user prompt this edit belongs to
}
interface Turn {
  index: number;
  prompt: string;        // the user message that started the turn (first 280 chars)
  summary: string;       // the last assistant text block of the turn (first 600 chars)
  files: string[];
}
```

Session selection: default to the most recent session whose `cwd` is the repo root (or inside it), with a picker (`:session`) for the others. Show the session's `summary` line (if one exists) as the title in the tape, otherwise the first prompt.

### 3.3 Intent groups
v1, deterministic: **one group per turn**. The group title is the turn prompt shortened to about 6 words and upper-cased; the briefing text is the turn's final assistant message. A file edited in several turns belongs to its **last** turn. The briefing also lists the other turns ("also touched in turn 2").

Fixed groups after the turns:
- **UNATTRIBUTED**: changed files that no ledger entry covers (my own edits, `Bash` side effects). Always shown, never masked.
- **GENERATED & LOCKFILES**: noise (§3.4), masked by default.

v2 (optional, behind a setting): ask Claude to cluster the files into 3–6 intents by running `claude -p` with the ledger and diffstat, and cache the result per session and diff hash. Never send file contents unless a setting allows it. Work repos can carry GDPR/ISO 27001 constraints.

### 3.4 Noise (relevance)
Default globs, overridable in `.debrief.toml` at the repo root:
```
*.lock  pnpm-lock.yaml  package-lock.json  yarn.lock  bun.lockb  Cargo.lock
**/__generated__/**  **/*.gen.ts  **/routeTree.gen.ts  **/*.snap
**/dist/**  **/build/**  **/*.min.js  **/openapi.json
```
Noise files still count in the header totals, but not in review progress.

### 3.5 Flags ("needs a closer look")
Each flag has a short reason string. v1 rules:
1. The file changed but isn't in the ledger (unattributed) and isn't noise.
2. Added lines contain `TODO`, `FIXME`, `XXX`, `@ts-ignore`, `eslint-disable`, `as any`, `.only(`, `.skip(`.
3. A test file was deleted, or more than 30% of a test file's lines were removed.
4. A `.env*` file changed, or added lines match a secret pattern (`AKIA…`, `-----BEGIN`, `sk-…`, long base64 after `KEY=`/`SECRET=`/`TOKEN=`). Show only the pattern name, never the value.
5. Conflict markers are present.
6. More than 400 changed lines in a non-noise file ("large change").

## 4. Review state

Stored in `.git/debrief/<session-id>.json` (never in the working tree):

```ts
interface ReviewState {
  sessionId: string;
  viewed: Record<string, string>;         // path -> worktree blob oid at the time it was marked viewed
  verdicts: Record<string, "keep" | "revert">; // hunkId -> verdict
  notes: { id: string; path: string; hunkId?: string; text: string; createdAt: string }[];
  transmitted: { at: string; noteIds: string[]; mode: TransmitMode }[];
}
```
- **Viewed is invalidated automatically** when the file's current blob oid differs from the stored one (Claude or I changed it again). The row goes back to OPEN and the command bar says `auth.guard.ts changed since cleared`.
- A verdict for a hunk id that no longer exists is dropped silently.

## 5. Actions

| Action | Key | Effect |
|---|---|---|
| Next / prev file | `j` / `k` (list), `J` / `K` (from anywhere) | follows the current grouping order, wrapping around |
| Scroll diff | `ctrl+d/u/f/b`, `g`/`G` | as in git-ui |
| Next / prev hunk | `]` / `[` | |
| Toggle viewed | `v` | |
| Clear & next | `space` | mark viewed, go to the next OPEN file |
| Keep / revert hunk | `y` / `x` | toggles; pressing it again clears the verdict |
| Note on file / hunk | `n` | focus composer, hunk-scoped if a hunk has the cursor |
| Transmit notes | `f` | see §6 |
| Stage cleared | `a` | stage every viewed, non-reverted file (hunks marked revert are left unstaged) |
| Discard reverted | `d` | confirm modal listing hunks → reverse-apply each hunk to the working tree |
| Toggle grouping | `t` | intent ↔ tree |
| Filters | `1` all · `2` open · `3` flagged · `m` toggle noise mask | |
| Path filter | `/` | |
| Session picker | `:session` | palette |
| Refresh | `R` | the watcher also refreshes automatically (debounced 300 ms) |
| Help | `?` | overlay generated from BINDINGS |

Discard implementation: build a single-hunk patch and apply it in reverse to the working tree (`git2::Repository::apply` with `ApplyLocation::WorkDir` on a reversed diff, or `git apply -R` as a fallback). If it fails because the file changed, show a toast and don't touch the file.

## 6. Transmitting notes to Claude

Notes are formatted as one prompt:

```
Review feedback from Debrief (session <id>, <n> notes):

1. apps/api/src/auth/auth.guard.ts (hunk @@ -8,9 +11,13 @@)
   Add a users.realm column + Drizzle migration before relying on session.user.realm.
2. …

Reverted hunks (already discarded from the working tree): <list or "none">.
Please address the notes, then stop so I can review again.
```

Modes (setting, default **clipboard**):
1. **clipboard**: copy the prompt, toast `copied · paste into your Claude session`.
2. **file**: write `.git/debrief/feedback.md` and copy `Read .git/debrief/feedback.md and address it.`
3. **resume** (explicit opt-in): run `claude --resume <session-id> -p "<prompt>"` as a child process and stream the output into the command bar or an output drawer. Warn if the session looks active (its transcript was written in the last 60 s).

Once sent, notes move to `transmitted` and the queue empties. The command bar reads `transmitted n notes to claude · awaiting next turn`.

## 7. Tauri commands

```
repo_open(path) -> RepoInfo
repo_status() -> RepoStatus                      // reuse git-ui
diff_file(path) -> FileDiff                      // HEAD vs workdir, with hunk ids
sessions_list() -> SessionInfo[]                 // for this repo, newest first
ledger_load(session_id) -> { turns: Turn[], entries: LedgerEntry[] }
review_model(session_id) -> ReviewModel          // files + groups + noise + flags + state, computed in Rust
review_set_viewed(path, viewed) -> ()
review_set_verdict(hunk_id, verdict | null) -> ()
notes_add(path, hunk_id?, text) -> Note
notes_remove(id) -> ()
notes_transmit(mode) -> TransmitResult
stage_cleared() -> { staged: string[] }
discard_reverted() -> { discarded: string[], failed: {hunkId, reason}[] }
```
Events: `repo://changed` (from the watcher; also watch the session's transcript file so a new Claude write shows up live) and `review://updated`.

## 8. Out of scope for v1
Committing, branches, stash, remotes (use git-ui). Split diff view. Multi-repo. Windows.
